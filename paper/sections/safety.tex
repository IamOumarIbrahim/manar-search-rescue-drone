\section{Safety, Authorization, and Failsafes}

Safety rules and deterministic monitoring logic are enforced directly within the C++ control core.

\subsection{Supervised Operator Authorization Rules}
To maintain operational integrity in high-stakes SAR environments, MANAR enforces six core supervisory rules:
\begin{enumerate}
    \item \textbf{Human Confirmation Authority:} Machine learning models gate candidate alerts, but only the human operator is authorized to assign \emph{Probable Rescuee} status.
    \item \textbf{Multi-Sensor Consensus:} No single sensor modality dominates victim confirmation; multi-modal evidence correlation is required.
    \item \textbf{Supporting Modality Principle:} Thermal LWIR and passive RF detections are treated strictly as supporting cues, avoiding false alarms from heated terrain or abandoned devices.
    \item \textbf{Guidance Authorization:} Active signaling devices (beacon, strobe, spotlight, smoke) require explicit operator authorization before activation.
    \item \textbf{Restricted Smoke Deployment:} Smoke marker release is strictly prohibited near fire-prone vegetation, fuel storage, crowds, or adverse wind conditions.
    \item \textbf{Safety Precedence:} Flight safety, airframe structural limits, icing risk, and minimum return energy strictly override search or detection confidence.
\end{enumerate}

\subsection{Communications Resilience and Link-Loss Logging}
Low-bandwidth flight telemetry ($2\text{--}10\text{ Hz}$) is transmitted across the primary encrypted command-and-control channel independently of high-bandwidth video streams ($SYS\text{-}R\text{-}03$). During total external communication loss, the control core logs all telemetry, flight modes, and sensor health data to onboard non-volatile storage while executing link-loss contingencies.

\subsection{Battery Failsafe Hierarchy}
The control core monitors battery percentage $B_k$ on every loop iteration:
\begin{equation}
\operatorname{Action}(B) = \begin{cases}
\text{Emergency Land}, & B_k \le B_{\mathrm{land}} \\
\text{Emergency RTL}, & B_k \le B_{\mathrm{emergency\_rtl}} \\
\text{Recommend RTL}, & B_k \le B_{\mathrm{rtl\_warn}} \\
\text{Battery Warning}, & B_k \le B_{\mathrm{warn}} \\
\text{Normal Operation}, & \text{otherwise}
\end{cases}
\end{equation}
When $B_k \le B_{\mathrm{emergency\_rtl}}$, \texttt{activateRTL()} automatically preempts active search and commands Return-to-Launch navigation to home base.

\subsection{Software Command Clamps}
All velocity and altitude command arguments are validated against software clamps prior to execution:
\begin{align}
v_{\mathrm{cmd}} &\le v_{\max} \\
H_{\mathrm{cmd}} &\le H_{\max}
\end{align}
Commands exceeding these limits are clamped, logging \texttt{WARN} events to \texttt{runtime/logs.txt}.
