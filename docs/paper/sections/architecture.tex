\subsection{Target State Ownership Architecture}
MANAR's selected target architecture assigns authoritative runtime state to the C++ Control Core. Under this design, state modifications requested by operators or triggered by safety rules would be evaluated and committed exclusively by the control layer. Subsystems would report evidence and health rather than directly mutating shared state.

\textit{Current evidence boundary:} several prototype subsystem functions still persist runtime data directly via \texttt{saveRuntime()}. The source therefore represents a transition toward centralized ownership, not a completed single-writer architecture.

\subsection{Communication \& IPC Architecture}
The communication architecture distinguishes between current prototype IPC and the selected final interface design:
\begin{itemize}
    \item \textbf{Current Prototype Data Flow:} File-backed JSON contracts under \texttt{runtime/} handle prototype communication and state persistence: \texttt{commands.json} serves as the command/request transport from the terminal to the control application, \texttt{runtime.json} provides the live prototype status representation, and \texttt{search\_locations.json} stores the persisted locked search-plan representation written by \texttt{control.cpp} upon processing location entry commands.
    \item \textbf{Selected Target Architecture (planned):} Real-time WebSocket + JSON protocol between a React/TypeScript GUI and the C++ control core. In this target model, \texttt{runtime.json} is retained as an on-demand snapshot export rather than the live transport.
\end{itemize}
